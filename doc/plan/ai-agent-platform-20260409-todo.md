# Sirix AI Agent 平台后续 TODO

本文记录当前主功能完成后的高价值补强项，目标是继续提升可靠性、稳定性、安全性和可维护性。

## 优先级建议

建议优先顺序：

1. 端到端自动化测试
2. 审批策略覆盖审计
3. 运行时垃圾回收
4. 工作区级配置 UI 化
5. 审计与可观测性增强

## 1. 端到端自动化测试

目标：

- 为 `sirix -> desktop-server -> Terminal -> 审批弹窗 -> resolve -> 缓存命中` 关键链路建立自动化回归测试。

原因：

- 当前已通过 `cargo check` 和 `flutter analyze`，但还缺少完整的跨模块行为验证。
- 这一层最能降低未来重构或补功能时引入回归的风险。

建议覆盖：

- 本地启动 AI session
- Terminal 输出同步
- 审批请求弹出
- `allow once / allow session / deny` 三种决策行为
- `once` 缓存消费后失效
- `session` 缓存重用
- 审批写入 backend 审计

## 2. 审批策略覆盖审计

目标：

- 系统检查所有实际工具入口，确保 `builtin / MCP / skills / shell` 的执行都统一经过审批检查。

原因：

- 目前审批模型、缓存和 UI 链路已经具备，但仍需要确认是否所有运行时入口都真正接入了这套策略。
- 如果存在绕过审批的入口，会直接削弱安全性设计。

建议输出：

- 一份能力清单
- 每项能力的审批入口位置
- 尚未接入审批的缺口清单

## 3. 运行时垃圾回收

目标：

- 为 `~/.sirix/runtime/sessions/` 和 `~/.sirix/runtime/approvals/` 增加清理策略。

原因：

- 当前会话目录和审批缓存已经持久化，但长期运行后会积累历史脏数据。
- 缺少回收机制会影响磁盘占用、排障体验和历史状态可控性。

建议方向：

- 按最后活跃时间清理过期 session
- 清理无对应活动 session 的 approval 文件
- 保留最近 N 个会话的运行时目录
- 提供手动清理命令或后台定时清理

## 4. 工作区级配置 UI 化

目标：

- 在 Desktop App 中增加当前工作区 `.sirix` 配置的查看与编辑入口。

原因：

- 当前工作区级配置加载和 `.sirix /.codex` fallback 已支持，但 UI 侧主要还是全局配置。
- 对使用多个项目的用户来说，没有工作区级可视化入口，配置体验仍不完整。

建议范围：

- 展示当前工作区生效配置来源
- 编辑工作区级 skills / MCP / agent 覆盖项
- 明确标识全局配置与工作区覆盖的差异

## 5. 审计与可观测性增强

目标：

- 补强关键路径日志、错误提示与审计信息。

原因：

- 当前主功能可用，但复杂故障场景下还需要更明确的可观测性来支撑定位问题。
- 这部分对后续稳定运行和线上排障价值很高。

建议增强点：

- MCP 校验失败日志和用户提示
- 审批拒绝事件审计
- 配置保存失败原因透出
- session 恢复失败和 attach 失败日志
- 审批缓存命中/失效的调试日志
